# سناریوی تست دستی — فاز ۲ (احراز هویت)

پس از `npm run db:reset` یا `npm run db:seed` حساب‌های زیر موجودند:

| کاربر | رمز | نقش |
|---|---|---|
| `admin` | مقدار `ADMIN_INITIAL_PASSWORD` (پیش‌فرض `Admin@123456`) | ADMIN — تغییر رمز اجباری |
| `staff1` | `Staff@123456` | STAFF |

---

## ۱) STAFF به `/admin` دسترسی ندارد

1. بروید به `/login`.
2. با `staff1` / `Staff@123456` وارد شوید.
3. باید به `/me` هدایت شوید.
4. در نوار آدرس `/admin` را باز کنید.
5. **نتیجه مورد انتظار:** به `/me` برگردید (لایه `requireUser` در layout ادمین با نقش‌های مجاز `ADMIN|MANAGER`).
6. حتی اگر HTML صفحه ادمین را ببینید، Server Actionهای ادمین بدون `requireUser`/`requirePermission` کار نخواهند کرد (middleware تنها هدایت است).

---

## ۱‑ب) Rate limit بر اساس IP

علاوه بر قفل حساب، بیش از **۲۰ تلاش ورود از یک IP در ۱۵ دقیقه** با پیام محدودیت پاسخ داده می‌شود (در حافظه سرور).

## ۲) قفل حساب بعد از ۵ تلاش ناموفق

1. خارج شوید (دکمه خروج).
2. در `/login` با نام کاربری `staff1` و **رمز اشتباه** وارد شوید.
3. پیام را بخوانید: باید **«نام کاربری یا رمز عبور نادرست است»** باشد (یکسان برای نام کاربری/رمز اشتباه).
4. همین کار را تا **۵ بار** تکرار کنید.
5. در تلاش پنجم (یا بلافاصله بعد از آن) پیام **قفل حساب** نمایش داده شود:
   «حساب موقتاً قفل شده است. لطفاً بعداً تلاش کنید»
6. حتی با رمز **صحیح** تا پایان ۱۵ دقیقه نباید وارد شوید.
7. برای باز کردن سریع در محیط توسعه می‌توانید در DB فیلدهای `locked_until` و `failed_login_count` را پاک کنید، یا ۱۵ دقیقه صبر کنید.

بررسی پیام یکسان برای نام کاربری اشتباه:

1. با نام کاربری `nobody-xyz` و هر رمزی تلاش کنید.
2. همان پیام «نام کاربری یا رمز عبور نادرست است» باید بیاید (نه «کاربر یافت نشد»).

---

## ۳) تغییر رمز اجباری admin

1. با `admin` و رمز اولیه وارد شوید.
2. باید به `/change-password` هدایت شوید و تا تغییر رمز به `/admin` نرسید.
3. رمز را عوض کنید؛ سپس به داشبورد ادمین بروید.
4. سشن‌های قبلی با افزایش `session_version` باطل می‌شوند.

---

## ۴) باطل شدن سشن با افزایش `session_version`

1. با `staff1` در یک مرورگر وارد شوید.
2. در SQLite مقدار `session_version` همان کاربر را دستی +۱ کنید (یا رمز را از سمت ادمین ریست کنید وقتی فاز ۳ آماده شد).
3. صفحه را رفرش کنید → باید به `/login` برگردید.
