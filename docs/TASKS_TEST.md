# سناریوی تست دستی — فاز ۵ (کارها و پایش)

پس از `npm run db:reset` در محیط development و تغییر رمز اجباری `admin`:

| کاربر | رمز | نقش | دپارتمان |
|---|---|---|---|
| `admin` | از `.env` | ADMIN | — |
| `manager1` | `Manager@123456` | MANAGER | عملیات |
| `staff1` | `Staff@123456` | STAFF | عملیات |
| `staff2` | `Staff@123456` | STAFF | پشتیبانی |

---

## ۱) فرم تعریف کار و پیش‌نمایش

1. با `admin` به `/admin/tasks/new` بروید.
2. عنوان بگذارید؛ نوع تکرار را عوض کنید و ببینید فیلدهای الگو پویا عوض می‌شوند.
3. برای روزانه، «جمعه» را در روزهای حذف‌شده بزنید → پیش‌نمایش (با تأخیر ~۴۰۰ms) ۱۰ تاریخ شمسی با نام روز هفته نشان دهد و جمعه در لیست نباشد.
4. الگوی بدون تاریخ معتبر (مثلاً پایان قبل از شروع) → هشدار اعتبارسنجی؛ الگوی بدون نتیجه → هشدار پیش‌نمایش.
5. بدون گیرنده ذخیره کنید → خطا: حداقل یک گیرنده.
6. یک دپارتمان + یک پرسنل همان دپارتمان را انتخاب کنید → «تعداد نهایی افراد» تکراری‌ها را حذف کند.
7. ذخیره → occurrence دوره جاری ساخته شود؛ در `/admin/board` سلول مربوط دیده شود.

## ۲) کپی، ویرایش الگو، آرشیو

1. از لیست کارها «کپی» را بزنید → فرم با داده‌های مشابه و عنوان «(کپی)» باز شود.
2. کار دارای occurrence را ویرایش کنید و نوع تکرار را عوض کنید → پس از ذخیره پیام «از فردا اعمال می‌شود» بیاید.
3. «آرشیو» بزنید → `is_active=false`؛ PENDING بدون پاسخ دوره جاری حذف شود؛ DONE/MISSED بماند.
4. حذف فیزیکی از UI ممکن نباشد.

## ۳) لیست و describeRecurrence

1. فیلتر دسته / نوع تکرار / فعال‌آرشیو / دپارتمان را امتحان کنید.
2. جستجو با `ي` عربی عنوانی با `ی` فارسی را پیدا کند.
3. ستون الگو متن طبیعی نشان دهد (مثلاً «هر روز به‌جز جمعه»، «هر ۲ هفته، دوشنبه»، «آخرین روز هر ماه»).

## ۴) محدوده MANAGER

1. با `manager1` وارد شوید.
2. کار جدید: فقط دپارتمان عملیات قابل انتخاب باشد؛ اساین به `staff2` ممکن نباشد.
3. کاری که admin به پشتیبانی هم اساین کرده را ببیند (اگر حداقل یک گیرنده در عملیات دارد) ولی ویرایش نتواند اگر گیرنده‌ای خارج از محدوده دارد.
4. کاری که همه گیرنده‌هایش در عملیات‌اند را ویرایش کند.

## ۵) پایش روزانه و معافیت

1. `/admin/board` را باز کنید (پیش‌فرض امروز).
2. روز قبل/بعد و تب‌های «این هفته» / «این ماه» را چک کنید.
3. خلاصه بالا: درصد انجام، بی‌پاسخ، لیست بدون پاسخ.
4. روی یک سلول کلیک کنید → وضعیت را با دلیل عوض کنید؛ در audit_logs ثبت شود.
5. «معافیت گروهی»: `staff1` و بازه شامل امروز + فردا → occurrenceهای بازه EXCUSED؛ رکورد `staff_leaves` بماند تا generate آینده همان روزها را مستقیم EXCUSED بسازد.

## ۶) انتقال دپارتمان (تکمیل فاز ۴)

1. کاری فقط روی دپارتمان عملیات تعریف کنید؛ برای `staff1` امروز PENDING بسازید.
2. `staff1` را به پشتیبانی منتقل کنید.
3. PENDING فقط‌دپارتمانی عملیات حذف شود؛ برای کارهای دپارتمان پشتیبانی از همان روز occurrence ساخته شود.
4. `department_joined_at` به امروز به‌روز شود.
